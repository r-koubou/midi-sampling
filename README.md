# wav-silence-trimmer

サンプリングした WAV ファイルの先頭・終端に含まれる無音相当区間を、高精度に自動検出して削除する CLI ツールです。

後段で実行するサスティンループ検出処理の前処理として使用します。固定 dB 閾値ではなく、各入力ファイルの先頭・終端に含まれる約 1 秒の余白から録音系のノイズフロアを推定し、そのノイズフロア相対のヒステリシス閾値で有音区間を検出します。

## 前提条件

- Python 3.12 以上
- [uv](https://docs.astral.sh/uv/) がインストールされていること

### 入力 WAV の前提

入力 WAV には、ノイズフロア測定用として先頭・終端それぞれに**約 1 秒の無音余白**が必要です。余白には意図的な発音を含めず、録音系由来のノイズのみが含まれるようにしてください。

推奨録音手順:

```text
録音開始 → 約1秒の無音余白 → MIDI Note On → 発音 → MIDI Note Off
→ リリースが十分減衰 → 約1秒の無音余白 → 録音終了
```

録音ごとに音源の出力レベル、オーディオインターフェースの入力ゲイン、ケーブル、サンプルレート、ビット深度、チャンネル構成を一定にしてください。

## セットアップ

```bash
uv sync
```

## 使い方

### 単一ファイル

```bash
uv run wav-trim input.wav --output output.wav
```

### ディレクトリ一括処理

```bash
uv run wav-trim ./samples --output-dir ./trimmed
```

サブディレクトリも処理する場合:

```bash
uv run wav-trim ./samples --output-dir ./trimmed --recursive
```

### ドライラン(書き込みせず検出結果のみ表示)

```bash
uv run wav-trim input.wav --output output.wav --dry-run --verbose
```

### JSON レポート

```bash
uv run wav-trim ./samples --output-dir ./trimmed --report-json ./trim-report.json
```

## 主要パラメーター

| オプション | デフォルト | 説明 |
|---|---:|---|
| `--edge-noise-seconds` | `1.0` | 先頭・終端からノイズ推定に使用する秒数 |
| `--noise-percentile` | `20.0` | 端部レベル分布からノイズフロアを求めるパーセンタイル |
| `--on-margin-db` | `15.0` | ノイズフロアに加算する開始判定マージン |
| `--off-margin-db` | `8.0` | ノイズフロアに加算する継続判定マージン |
| `--minimum-on-ms` | `10.0` | 開始判定に必要な連続有音時間 |
| `--bridge-gap-ms` | `80.0` | 有音として連結する短い無音ギャップ |
| `--pre-roll-ms` | `8.0` | 検出開始点より前に残す余白 |
| `--post-roll-ms` | `40.0` | 検出終了点より後に残す余白 |
| `--fade-in-ms` / `--fade-out-ms` | `1.0` / `5.0` | 出力端の短いフェード(`--no-fade` で無効化) |

全オプションは `uv run wav-trim --help` を参照してください。

### 音色別の設定例

アタックが遅いパッド・ストリングス系:

```bash
uv run wav-trim input.wav --output output.wav \
  --on-margin-db 12 --minimum-on-ms 20 --pre-roll-ms 20
```

リリースが長い音色:

```bash
uv run wav-trim input.wav --output output.wav \
  --off-margin-db 6 --bridge-gap-ms 150 --post-roll-ms 80
```

## 有音検出不能時の対処

余白がノイズのみで有音区間が見つからない場合、そのファイルは警告付きでスキップされます(`--fail-on-no-signal` 指定時は失敗扱い)。以下を確認してください。

- 発音レベルがノイズフロアより十分大きいか(`--on-margin-db` を下げると検出しやすくなります)
- 先頭・終端の余白に発音が混入していないか
- ファイル全体が発音で埋まっていないか(端の余白が前提のため、全体有音のファイルは検出不能になります)

## 設計上の注意事項

- **音量ノーマライズは行いません。** 信号とノイズが同じ倍率で増幅されるため S/N 比は改善せず、クリッピングやファイル間の相対レベル情報の破壊を招くだけだからです。内部計算は float64 で行い、微小レベルでも精度を確保しています。
- **`smpl` チャンクは扱いません。** サンプルレート・チャンネル数・サンプル形式(サブタイプ)の維持を主要要件とし、未知チャンクの完全維持は保証しません。
- 本ツールはサスティンループ検出の**前処理**です。途中の休符や音量低下(トレモロ等)は削除せず、最初の発音から最後の減衰までを 1 区間として保持します。
- 出力は一時ファイル経由で原子的に置換するため、書き込み途中の失敗で不完全なファイルが残ることはありません。

## ローカルでの実ファイル検証

実サンプル(ピアノ系の短いアタック、ストリングス系の遅いアタック、パッド系の長いリリース、トレモロ音色、左右定位の強い音色、低/高ベロシティー音、録音ノイズが大きめのファイルなど)を用意し、以下で検証できます。

```bash
uv run wav-trim ./local-samples --output-dir ./local-trimmed \
  --dry-run --verbose --report-json ./local-report.json
```

`--dry-run` で検出境界を確認し、問題なければ `--dry-run` を外して実行してください。

uv run pytest

## 終了コード

| コード | 意味 |
|---:|---|
| `0` | 全処理成功 |
| `1` | 一部または全部のファイル処理失敗 |
| `2` | CLI 引数不正 |
| `3` | 入力ファイルまたはディレクトリ不正 |
| `4` | 有音区間検出不能(`--fail-on-no-signal` 指定時) |
| `5` | 出力書き込み失敗 |
