  実装内容

  仕様書(AGENTS.md)に沿って wav-silence-trimmer パッケージを新規実装しました。

  プロジェクト構成 — pyproject.toml を仕様通りに書き換え(wav-trim
  エントリポイント、numpy/scipy/soundfile 依存、hatchling ビルド)、uv sync
  で環境構築できます。

  モジュール(CLI 層と信号処理層を分離):
  - detector.py (src/wav_silence_trimmer/detector.py) —
  検出パイプライン本体。中央値による DC 除去 → 累積和ベースのフレーム
  RMS(チャンネル最大値を代表値に採用)→ dBFS 変換 + 3点メディアンフィルタ →
  端部約1秒の20パーセンタイルによるノイズフロア推定 → ヒステリシス閾値(on/off)→
  最小連続時間による開始候補検出 →
  モルフォロジークロージングでトレモロ等の短いギャップを連結 →
  開始候補を含む連結成分のみ採用 → 1ms窓・0.25msホップでの境界高精度再探索 →
  プリロール・ポストロール付加
  - audio_io.py (src/wav_silence_trimmer/audio_io.py) —
  サブタイプ維持の読み書き、一時ファイル経由の原子的置換、上書き制御
  - fade.py (src/wav_silence_trimmer/fade.py) —
  全チャンネル同一ゲインの線形フェード(実際にトリミングした側のみ適用)
  - cli.py (src/wav_silence_trimmer/cli.py) — argparse
  による全オプション、ディレクトリ一括・再帰処理、JSON レポート、終了コード 0〜5
  - models.py (src/wav_silence_trimmer/models.py) / config.py
  (src/wav_silence_trimmer/config.py) / errors.py
  (src/wav_silence_trimmer/errors.py) —
  データクラス、デフォルト値と妥当性検証、独自例外

  検証結果 — 合成音声(48kHz ステレオ PCM_24、1秒ノイズ + 2秒トーン +
  1秒ノイズ)での実行で、ノイズフロア -80.0 dBFS を正しく推定し、境界誤差は約
  0.75ms(許容 ±10/±30ms
  に対して十分)、サブタイプ・サンプルレート・チャンネル数も維持されました。

  仕様と異なる判断が1点 —
  「全体が有音」のテストケースは、端部余白からノイズフロアを推定する仕様上、フロ
  アが信号レベルと一致して検出不能(NoSignalDetectedError)になります。これは仕様
  8.5/8.7
  の帰結であり、前提条件(約1秒の余白)違反の入力なので、その挙動を正として
  テストに理由をコメント付きで記載 (tests/test_detector.py) し、README
  の「有音検出不能時の対処」にも明記しました。

  README.md にはセットアップ、使用例、音色別(遅いアタック/長いリリース)の設定例
  、ノーマライズを行わない理由、smpl チャンク非対応などを記載しています。コミッ
  トはまだ行っていません。必要であればお申し付けください。

  ました(全70テスト成功)。
